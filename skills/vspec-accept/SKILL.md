# VSpec Accept Skill

Generates scenario-driven acceptance test cases (JSON) from detailed specifications, covering happy path, exceptions, boundaries, permissions, and data scope.

## When to Use

Invoke this skill when:
- Spec artifacts exist under `/specs/` (generated by earlier skills).
- User runs `/vspec:accept` to generate acceptance test cases.
- The team needs structured, scenario-driven acceptance cases for QA and validation.

## Prerequisites

This skill requires artifacts produced by earlier skills:
- `/specs/functions/*` — function list (required, from `vspec-new`)
- `/specs/background/scenarios.md` — scenario list (required, from `vspec-new`)
- `/specs/background/scenario_details/` — scenario details (recommended)
- `/specs/background/roles.md` — role definitions (recommended)
- `/specs/models/*.md` — data models (recommended)

## What This Skill Defines

- Generate scenario-driven acceptance test cases in structured JSON format.
- Cover happy path, exception handling, boundary conditions, permission checks, and data scope validation.
- Provide a trilingual testcase reader HTML page for interactive review.
- This skill generates test case definitions — not executable test code.

## Scope Boundary

This skill produces acceptance test case definitions only. It does NOT:
- Generate executable test code (Playwright scripts, unit tests, etc.).
- Execute or run any tests.
- Modify spec artifacts.

For executable test automation, use:
- `vspec-script` → Playwright automation scripts from JSON cases
- `vspec-append-test` → framework-specific test code generation

## Command

### `/vspec:accept`

Use this command to generate acceptance test cases.

Language:
- Read `/scheme.yaml` `selected.language` (supports `en`, `zh`, `ja`; default to `en` if missing/invalid).
- All acceptance artifacts under `/test/验收用例/` must use the selected language consistently.

Flow:
1. Read `/specs/functions/*`, `/specs/background/scenarios.md`, `/specs/background/scenario_details/`, `/specs/background/roles.md`, `/specs/models/*.md`.
2. Ensure `/test/` exists, and ensure subfolders exist:
   - `/test/验收用例/`
   - `/test/单元测试/`
   - `/test/集成测试/`
   - `/test/playwright/`
3. Copy the built-in testcase reader HTML `prompts/testcase_reader.html` to `/test/testcase_reader.html` (overwrite). The template has built-in trilingual support.
4. Load `prompts/accept.md` to generate scenario-driven acceptance test cases (JSON) covering happy path, exceptions, boundaries, permissions, and data scope.
5. Write acceptance cases to `/test/验收用例/acceptance_cases.json`.
6. Return the generated case summary. STOP. For executable test automation, use `vspec-script` to generate Playwright scripts from these cases.

## Prompt Files

- `prompts/accept.md`: the main prompt for generating scenario-driven acceptance test cases.
- `prompts/testcase_reader.html`: built-in trilingual HTML template for the testcase reader page.

## Suggested Workflow

1. Ensure prerequisite specs exist under `/specs/` (run `vspec-new` → `vspec-detail` → `vspec-verify` first if needed).
2. Run `/vspec:accept`.
3. The skill reads scenarios, roles, models, and function lists.
4. It generates a structured JSON file of acceptance test cases.
5. A testcase reader HTML page is provided for interactive review.
6. Review the cases at `/test/testcase_reader.html`.
7. For Playwright automation, proceed with `vspec-script`.

## Output Goal

This skill produces acceptance test case definitions:

- Scenario-driven acceptance cases in `/test/验收用例/acceptance_cases.json`.
- A trilingual testcase reader HTML page at `/test/testcase_reader.html`.
- Cases covering happy path, exceptions, boundaries, permissions, and data scope.

Output is limited to test case definitions. Executable test code generation is handled by `vspec-script` and `vspec-append-test`.
