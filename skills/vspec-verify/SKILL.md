# VSpec Verify Skill

Generates data models and a runnable web prototype from detailed specifications, enabling stakeholders to validate behavior early through interactive prototypes before any production code is written.

## When to Use

Invoke this skill when:
- Detailed specs exist under `/specs/details/` (generated by `vspec-detail`).
- User runs `/vspec:verify` to generate models and prototypes.
- The team needs a runnable prototype for stakeholder review and scenario validation.

## Prerequisites

This skill requires artifacts produced by earlier skills:
- `/specs/details/` — per-function detailed specs (required, from `vspec-detail`)
- `/specs/functions/*` — function list (required, from `vspec-new`)
- `/specs/background/*` — requirement analysis (recommended)
- `/specs/flows/*.puml` — business flow diagrams (recommended)
- `/scheme.yaml` — tech stack selection (auto-created with defaults if missing)

If `/specs/details/` is missing or empty, instruct the user to run `/vspec:detail` first.

## What This Skill Defines

- Generate data model documents from detailed specs.
- Produce a runnable web prototype aligned with the selected tech stack in `/scheme.yaml`.
- Create role-based dashboards, scenario validation pages, and entry pages.
- Run post-generation quality checks (stack compliance, mobile selection, price formatting, click handling, completeness).
- This skill generates a **prototype for validation and review**, not production code.

## Scope Boundary

This skill ends at prototype and model generation for validation purposes. After completion, use other skills for later stages:
- `vspec-impl` → production-ready backend and frontend code generation
- `vspec-accept` / `vspec-i-test` → test case generation
- `vspec-qc` → quality checks on generated artifacts

Do NOT proceed to production implementation within this skill — that is handled by `vspec-impl`.

## Command

### `/vspec:verify`

Use this command to generate models and a runnable prototype for validation.

Language:
- Read `/scheme.yaml` `selected.language` (supports `en`, `zh`, `ja`; default to `en` if missing/invalid).
- Generate `/specs/models/` docs and all prototype UI copy in the selected language consistently.

Flow:
0. Ensure `/specs/details/` exists and is non-empty; if missing, stop and output the prerequisite message: "Run /vspec:detail to generate /specs/details/ before /vspec:verify".
1. If `/specs/background/questions.md` exists and contains unanswered questions, ask the user to answer them before continuing (allow skip per question, but ensure none remains unanswered).
2. Load `prompts/model.md` to generate data models.
3. Write model files to `/specs/models/*.md`.
4. Generate a runnable page prototype based on functions, details, models, and roles; the prototype tech stack can be selected via `/scheme.yaml` (auto-created with defaults if missing).
   - Load `prompts/prototype.md` for the prototype generation rules (must follow `scheme.yaml` stack; do not output html-only).
   - The prototype prompt references many sub-prompts for specific page types (dashboard, calendar, CRUD, apply, approve, execute, etc.) — all are available under `prompts/`.
5. Write the prototype to `/specs/prototypes/`.
6. Load `prompts/harness/verify/post_verify_stack_verify.md` to validate whether the prototype frontend stack matches `/scheme.yaml`. If it outputs any issues, show the issue list and stop.
7. Load `prompts/validation.md` to generate a scenario validation web page.
   - Use the built-in HTML template at `prompts/scenario.html` (copy verbatim, do not regenerate).
8. Write the validation page to `/specs/prototypes/` and provide a `scenario.html` entry for access.
9. Load `prompts/entries.md` to generate an entry page and write it to `/specs/prototypes/entries.html` (do not link it from any menu/header).
10. Load `prompts/harness/verify/post_verify_mobile_selection_check.md` to ensure mobile data selection uses a picker page (list-based), not dropdown Select. If it outputs any issues, show the issue list and stop.
11. Load `prompts/harness/verify/post_verify_price_format_check.md` to validate money/price formatting (right aligned, 2 decimals, thousand separators). If it outputs any issues, show the issue list and stop.
12. Load `prompts/harness/verify/post_verify_click_check.md` to detect clickable UI elements that do nothing. If it outputs any issues, show the issue list and stop.
13. Load `prompts/harness/verify/post_verify_verify.md` to validate the prototype completeness. If it outputs any issues, show the issue list and stop.
14. Return the generated prototype summary. STOP. Do NOT proceed to production code generation or implementation. The next stage (/vspec:impl) is handled by a separate skill — the user must invoke it when ready.

## Suggested Workflow

1. Ensure `/specs/details/` exists and is non-empty (run `/vspec:detail` first if needed).
2. Ensure `/scheme.yaml` exists with desired tech stack (auto-created with defaults if missing).
3. Run `/vspec:verify`.
4. The skill generates data models, a runnable prototype, and scenario validation pages.
5. Post-verify quality checks validate stack compliance, formatting, and completeness.
6. Review the prototype at `/specs/prototypes/` with stakeholders.
7. Stop. The prototype validation phase is complete. Suggest the user proceed with `vspec-impl` for production code generation when ready.

## Output Goal

This skill produces validation artifacts only:

- Data model documents under `/specs/models/`.
- A runnable web prototype under `/specs/prototypes/` aligned with `/scheme.yaml`.
- Role-based dashboards with proper chart selection and layout.
- A scenario validation page for reviewing key scenarios.
- An entry page for navigating all prototype views.

Output is limited to `/specs/models/` and `/specs/prototypes/`. The prototype is for **validation and review**, not production deployment. Production code generation is handled by `vspec-impl`.
