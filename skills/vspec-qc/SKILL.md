# VSpec QC Skill

Runs quality checks on generated requirement artifacts, producing a structured non-conformance checklist to surface omissions, contradictions, and quality issues before implementation.

## When to Use

Invoke this skill when:
- Spec artifacts exist under `/specs/` (generated by earlier skills: `vspec-new`, `vspec-detail`, `vspec-verify`).
- User runs `/vspec:qc` to run quality checks.
- The team wants to validate spec completeness before proceeding to implementation.

## Prerequisites

This skill reads artifacts under `/specs/` produced by earlier skills. No specific artifact is strictly required — the QC check adapts to what's available, but more artifacts produce more thorough checks.

## What This Skill Defines

- Read built-in quality standards (general and industry-specific).
- Merge project-level quality standards when available.
- Generate a non-conformance checklist against quality criteria.
- Output a structured QC report in markdown and JSON formats.
- This skill identifies issues — it does NOT fix them.

## Scope Boundary

This skill produces a quality check report. It does NOT:
- Modify any spec artifacts or fix identified issues.
- Generate code, prototypes, or test cases.
- Implement corrections — that is handled by other skills (`vspec-refine` for spec updates, `vspec-impl` for code).

After review of the QC report, the user should address issues using the appropriate skill for each type of correction.

## Command

### `/vspec:qc`

Use this command to run a quality check on the generated requirement artifacts under `/specs/`.

Note: The Pro edition supports broader quality checks (e.g. more post-run prototype/implementation verifications) and requires a paid plan.

Language:
- Read `/scheme.yaml` `selected.language` (supports `en`, `zh`, `ja`; default to `en` if missing/invalid).
- The QC report `/specs/qc_report.md` must use the selected language consistently.

Flow:
1. Read built-in standard at `prompts/quality_standard.md`.
2. If a requirement quality error book exists under project `qc/`, generate/update project root `quality_standard.md` based on it.
3. If project root `quality_standard.md` exists, merge it as supplementary/overriding standard.
4. Load `prompts/qc.md` and generate a non-conformance checklist.
5. Write the report to `/specs/qc_report.md` (and optionally `qc_report.json` / `qc_report.html` for interactive review).
6. Return the QC report summary. STOP. This skill identifies issues only — do NOT attempt to fix them. Corrections should be applied via `vspec-refine` or by the user directly.

## Prompt Files

### Core
- `prompts/quality_standard.md`: built-in general quality standard used as the baseline for all QC checks.
- `prompts/qc.md`: the main QC prompt that generates the non-conformance checklist and report.

### Industry-specific quality standards
- `prompts/banking_quality_standard.md`: banking/finance domain quality criteria.
- `prompts/logistics_quality_standard.md`: logistics/supply chain domain quality criteria.
- `prompts/pharmaceutical_quality_standard.md`: pharmaceutical domain quality criteria.
- `prompts/healthcare_quality_standard.md`: healthcare domain quality criteria.
- `prompts/manufacture_quality_standard.md`: manufacturing domain quality criteria.
- `prompts/govermental_quality_standard.md`: government/public sector quality criteria.
- `prompts/public_service_quality_standard.md`: public service domain quality criteria.
- `prompts/retail_quality_standard.md`: retail domain quality criteria.
- `prompts/e-commerce_quality_standard.md`: e-commerce domain quality criteria.
- `prompts/warehouse_quality_standard.md`: warehouse/inventory domain quality criteria.
- `prompts/tickets_quality_standard.md`: ticketing/booking domain quality criteria.
- `prompts/oa_quality_standard.md`: office automation domain quality criteria.
- `prompts/software_project_quality_standard.md`: general software project quality criteria.

### Templates and resources
- `prompts/qc_report.html`: built-in trilingual HTML template for the interactive QC report viewer.
- `prompts/需求分析错题本.xlsx`: built-in quality error book (reference for common requirement analysis pitfalls).

## Suggested Workflow

1. Ensure spec artifacts exist under `/specs/` (run prior skills if needed).
2. Run `/vspec:qc`.
3. The skill reads the built-in quality standard and any project-level overrides.
4. It generates a non-conformance checklist against all available spec artifacts.
5. Review the report at `/specs/qc_report.md` (or the HTML viewer).
6. Address issues using the appropriate skill (`vspec-refine` for spec updates, `vspec-new` for missing analysis, etc.).
7. Re-run `/vspec:qc` after fixes to verify resolution.

## Output Goal

This skill produces quality check reports only:

- A structured non-conformance checklist in `/specs/qc_report.md`.
- Optional JSON (`qc_report.json`) and HTML viewer for interactive review.
- Issues categorized by severity, type, and affected artifacts.

Output is limited to `/specs/qc_report.*`. The QC report identifies issues for review — corrections are handled separately.
